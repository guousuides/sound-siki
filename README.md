# demon — 打鍵を餌にする環境音デーモン

新幹線・特急禁止縛りで京都に行った帰り、Wi-Fi がないので AI なしでコードを書いていた。
イヤホンで音楽を流すと気が散る。かといって無音だとソワソワする。
イヤホンを外して、電車の走行音と蝉の声をそのまま BGM にしたら、いちばん集中できた。

YouTube で環境音を流せばいい、という話ではある。でも容量を食うし、何よりロマンがない。
**音を再生するのではなく、その場で合成する。しかも自分の打鍵を餌にして育つ。**
だから「デーモン」。

音声ファイルは 1 バイトも持たない。ネットにも一切つながらない。
ノイズと四則演算だけで、電車も蝉も風鈴も雀もその場で作る。

- 音源アセット: **0 バイト**（起動時に numpy で合成）
- ソース全体: **約 111 KB / 2,850 行**
- CPU: 両方のデーモンを全開で鳴らして **1 コアの約 5%**
- 依存: `numpy` / `sounddevice` / `pynput` のみ（コンパイラ不要）

---

## インストール

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

## 使い方

```powershell
.\.venv\Scripts\python.exe -m demon                # 路線を選んで乗る
.\.venv\Scripts\python.exe -m demon train cicada   # 電車 + 蝉
.\.venv\Scripts\python.exe -m demon cicada --volume 0.85   # 既定は 0.65
.\.venv\Scripts\python.exe -m demon --lines        # 路線一覧
.\.venv\Scripts\python.exe -m demon --list         # デーモン一覧
.\.venv\Scripts\python.exe -m demon --devices      # 出力デバイス一覧
```

同梱の `demon.ps1` を使えば `.\demon.ps1 train cicada` だけで済む。

電車デーモンは起動のたびに**どこからどこまで乗るか**を聞く。路線、向き、種別、
出発駅、目的駅の順に番号を打つだけで、Enter だけ押していけば既定が選ばれる。

```
  どの路線に乗りますか
    1  山手線        内回り／外回り    30駅  34.5km   地上・周回。ジョイントが主役。
    2  中央線快速      下り／上り        24駅  53.1km   地上・高速。駅間が長い。
    3  副都心線       渋谷方面／和光市方面  16駅  20.2km   地下・全駅ホームドア。
  > 3

  ── 副都心線 急行 ／ 小竹向原 → 渋谷 ／ 4駅 11.9km ／ 目安 15分 ──
```

**「目安 15 分」が出るのが肝**で、乗る前に今日の作業がどれくらいの長さか決まる。
毎回聞かれるのが煩わしければ、全部指定すれば飛ばせる:

```powershell
.\demon.ps1 train --line chuo --from 東京 --to 高尾 --kind 特別快速
.\demon.ps1 train --fresh            # 前回の続きを無視して乗り直す
.\demon.ps1 train --no-exit          # 終点に着いても終了しない
```

Ctrl+C でフェードアウトして終了。**目的駅に着いても終わる** —— 終点のアナウンスの
あと、ホームの音のまま 30 秒だけ余韻を置いて、走行サマリを出して眠る。

キーボードを触らずに音だけ確かめたいとき:

```powershell
.\demon.ps1 train --demo                            # 台本どおりの仮想タイピングで鳴らす
.\demon.ps1 train cicada --render out.wav --seconds 90   # WAV に書き出す
```

この 2 つは路線を聞かない（既定の山手線を走る）。

## 打鍵と音の結合

デーモンが食べているのは**文字ではなくリズム**。速さ・持続・間・訂正の 4 つだけを見ている。

| 打鍵から取り出す特徴 | 意味 |
|---|---|
| `kps` | 1 秒あたりの打鍵数（時定数 3 秒で平滑化） |
| `intensity` | `kps` を 0..1 に正規化し、**さらにもう一段（時定数 6〜8 秒）鈍らせた**駆動力 |
| `flow` | 「速いか」ではなく「**続いているか**」を溜める遅い蓄積器（時定数 15〜20 秒） |
| `idle` | 最後の打鍵からの経過秒 |

打鍵は本来むらがある —— 一気に書いて、手を止めて考えて、また書く。
これをそのまま音に流すと、こちらが息を切らしているのが全部聞こえてしまって落ち着かない。
なので平滑化を 2 段にしてある。**打鍵の突風は、そのまま突風にはならず、ゆっくりした潮の満ち引きになる。**

### 電車デーモン

```
打鍵の速さ    → 主幹制御器（ノッチ）。ただし電車には質量がある
訂正          → ノッチが浅くなる。迷いながらの運転は時間を作らない
車速          → ジョイント音の間隔・走行音の高さ・風切り音・VVVF の唸り
現在位置      → トンネル、曲線、分岐器、ホーム、そして放送
Enter         → 警笛（タイフォン）。ただし数分に一度まで
長い無音      → 惰行、やがてブレーキ。駅に着いていれば、ドアが閉まらない
```

肝は**質量**。速く打っても即座には加速しない。手を止めれば惰行し、そのままなら
運転士がブレーキを入れて停める。スイッチではなく、餌をやり続けないと走らない。

そして今度は**行き先がある**。線路の上を実際に距離で進んでいて、駅は必ず来る。

```
力行   a = 0.83 · notch · taper(v) − 走行抵抗(v)     起動加速度 3.0 km/h/s
惰行   a = − 走行抵抗(v)
制動   a = − 1.00 · b                                常用最大 3.6 km/h/s
       v += a·dt ,  x += v·dt
```

**ブレーキはあなたのものではない。** 毎ブロック、次の停車駅にちょうど止まるには
どれだけ減速が要るか —— `v² / 2d` —— を計算して、それが常用ブレーキの相応の割合に
達したら運転士が入れる。だからどれだけ速く打っても駅は来るし、駅では必ず停まる。
**主幹制御器はあなたのもので、ダイヤはそうではない。** この非対称が全部です。

速く打てば早く着く。ただし停車の多い路線では、効くのは駅を出るたびの加速だけ
なので差は 1 割前後にしかならない —— それは物理的に正しい。効くのはそこではなく、
**打つのをやめると進まない**ほう:

| 打鍵のしかた | 副都心線 急行 和光市→渋谷（目安 23 分） |
|---|---|
| ずっと打ち続ける | **24 分** |
| 3 分打って 3 分休む | 44 分 |
| 2 分打って 5 分休む | 72 分 |
| 10 分に 1 分だけ打つ | **191 分** |

駅に着いてしまえばもっと露骨で、**打鍵が途切れているとドアが閉まらない**。
そのまま放っておくと、車内にこう流れる:

> ♪ お客様にお知らせいたします。ただいま、お客様対応のため、当駅にてしばらく
> 停車しております。

サボると車内放送で咎められる。

### 乱数だったものが、地形になった

以前のこのデーモンは、Enter を押すとトンネルを、Backspace を押すと分岐器を
**サイコロで**出していた。位置を持ったので、全部そこにあるから鳴るようになった。

- トンネルは、その路線がトンネルに入る**メートル地点**にある
- 分岐器は、渡り線のある駅の**進入側**にある
- 曲線の軋りは、その曲線を通ったから鳴る
- ジョイントは `floor(x / 25)` が変わったから打たれる

副都心線は和光市を出てすぐ地下に潜る。その一回のトンネル突入は、Enter を押したから
ではなく、**そこにトンネルがあるから**起きる。

ジョイント音は数式で出している。日本の定尺レールは 25 m、台車の軸距は約 2.4 m、
台車間は約 14 m。だから 1 本の継ぎ目を 1 両が通過すると打音は 4 回 ——
「ガタン・ゴトン」—— で、その間隔は速度で割った値そのもの。

> なお副都心線は 2008 年開業のロングレールで、**本当はガタンゴトンは鳴らない**。
> ここは意図的にリアリティを曲げて、音量を 42% に絞って鳴らしてある。
> 電車デーモンにガタンゴトンがないのは寂しい、という理由だけで。

### 車内放送 —— 録音も TTS も使わずに喋らせる

制約がそのまま設計になっている。音声ファイルは 1 バイトも持たないし、ソケットも
開かない。だから放送は WAV ではありえないし、OS の読み上げでもありえない。
**ありうるのは、四則演算だけ。**

日本語はモーラ等時性の言語で、母音は 5 つしかない。つまり駅名は
**毎秒 7 拍ほどの、5 つの母音のリズム**にすぎない。

- 母音は加算合成。ある高さの倍音列に、3 つのフォルマント共振を掛ける
- 車内スピーカーの帯域（330〜3300 Hz）に絞り、短いタップを 2 つ足して鉄の箱に入れる
- 子音は 4 つの身振り —— 破裂、摩擦、鼻音、わたり —— を母音の前に置くだけ。
  粗いが、**音節の切れ目は出る。読めるかどうかを決めているのは切れ目のほう**
- 拗音・促音・撥音・長音は分解器が処理するので、路線データに読みがなを書けば喋る

一言も聞き取れない。**それは狙いどおり**で、意味のほうはターミナルに日本語で出る。
スピーカーから出るのは形だけ ——「駅名が何拍あるか」「どこで上がってどこで落ちるか」
—— で、半分しか聞いていない電車の中で実際に受け取っているのは、そっちのはず。

```
四ツ谷      よつや          → o-u-a        3 拍、短い
西荻窪      にしおぎくぼ     → i-i-o-i-u-o  6 拍、長い
```

だから**駅名が変わったことは、意味が取れなくても耳で分かる**。

声の高さはセッション開始時に 2 択から抽選される。今日の車掌が決まる。

### 肉声で喋らせる（VOICEVOX）

形だけでは物足りない日のために、**ローカルで動いている VOICEVOX があれば、
放送はそちらの声で喋る**。何もしなくても `auto` で探しにいき、見つからなければ
上のフォルマント合成に黙って戻る。

1. [VOICEVOX](https://voicevox.hiroshiba.jp/) を入れて起動しておく（エンジンが `127.0.0.1:50021` で待つ）
2. いつもどおり `.\demon.ps1 train` で乗る。起動時に `車内放送: VOICEVOX:ずんだもん（ノーマル）` と出れば肉声

```powershell
.\demon.ps1 train --speaker 8                      # 話者スタイル ID（既定 3 = ずんだもん）
.\demon.ps1 train --voicevox http://127.0.0.1:10101  # AivisSpeech など互換エンジン
.\demon.ps1 train --voice synth                    # 今までのフォルマント合成だけ
```

- エンジンには**漢字のままの文**を渡す（そのほうがアクセントが自然）。ただし駅名と
  種別だけは路線データの読みがなをカタカナにして差し込む ——「四ツ谷」「雑司が谷」は
  辞書がいちばん間違える単語だから
- 返ってくるのはスタジオ品質の声なので、フォルマントと**同じ天井スピーカーと鉄の箱**
  （330〜3300 Hz、短い反射 3 本）を通してから鳴らす
- 一度喋った文は `~/.demon/voice/` に WAV で残す。駅の放送は毎回同じ文なので、
  一周したあとは**エンジンを起動していなくても肉声で喋る**
- 通信は `127.0.0.1` のエンジンとだけ。プロキシも通さない。インターネットには出ない
- 合成に失敗したら、その乗車のあいだはエンジンを諦めてフォルマントで喋る。放送が
  落ちても電車は止まらない

> 声のクレジットは起動時に表示される（例: `VOICEVOX:ずんだもん`）。録音を公開する
> ときは各キャラクターの利用規約に従ってクレジットを付けること。

> 発車メロディは意図的に作っていない。あれは特定の誰かの著作物なので、
> 鳴るのは無個性な電鈴だけにしてある。

組み立ては丸ごと 1 本のバッファにしてからミキサに 1 声で渡す。20 拍の文が
リアルタイム側に払わせるコストは、ジョイント 1 本ぶんと同じ。合成そのものは
オーディオスレッドの外（専用スレッド）でやる —— 46 ms のブロックの中で
数ミリ秒を使うのは、遅いマシンで確実に音が途切れる。

### 蝉デーモン

```
flow          → 鳴いている個体数（遠くの 1 匹 … 蝉時雨）
Backspace 連発 → 近くの数匹が驚いて鳴き止み、じわじわ戻ってくる
Enter         → 縁側の風鈴（頻度は絞ってある）
20 分の持続    → ヒグラシが加わり、午後が夕方に傾きはじめる
```

蝉は「速さ」ではなく「**続いているか**」に反応する。
バーストで速く打っても増えない。淡々と続けているとだんだん厚くなる。
個体数は整数で増減するのではなく、境界の 1 匹が中途半端な音量で出入りするので、
厚みは**段ではなく勾配**で変わる。最大でも 8 匹ほどで頭打ちにしてある。

アブラゼミは 68 Hz の AM をかけた 3〜8 kHz のノイズ、ミンミンゼミは
「ミーン」から 9.5 Hz の「ミンミンミン」に割れていくフレーズ、
ヒグラシは 11 Hz のパルス。個体ごとに再生レート・定位・位相をずらしてあるので、
バッファは 3 本でも合唱は聞こえるかぎり繰り返さない。

### 「たまにしか起きない」ようにしてある

コーディング中の Enter は多い。素直に「Enter = 警笛」にすると踏切のたびに
鳴りっぱなしどころではないので、70〜190 秒のクールダウンを持たせてある。
風鈴も同じ理由で 35〜110 秒。Backspace も 1 回では蝉は驚かない
（4 回分の「圧」が溜まって初めて驚く）。

電車のトンネルと分岐器はこの仲間から抜けた。**いまはクールダウンではなく
位置で決まる**ので、間隔を人が決める必要がなくなった —— 線路がもう決めている。

残りの定数は各デーモンの `render()` 冒頭と `route.py` の頭にまとまっているので、
好みで変えられる。

## プライバシー

これはグローバルキーフックを張る。つまり技術的にはキーロガーと同じ入り口を使う。
だから設計として、**入り口で捨てている**:

`demon/keywatch.py` の `on_press` から外に出るのは `0..3` の整数（文字 / スペース /
訂正 / 改行）だけ。文字もキーコードもウィンドウタイトルもタイムスタンプも
保持しない。ネットワークにも出さない（開くソケットは、VOICEVOX を使うときの 127.0.0.1 宛てだけ）。
Shift や Ctrl などの修飾キーは数える前に捨てている。

### 唯一ディスクに書くもの

行き先ができたので、`~/.demon/journey.json` に 1 ファイルだけ書くようになった。
中身は全部で 8 項目、実物がこれ:

```json
{ "version": 1, "line": "chuo", "kind": "特別快速", "direction": 1,
  "origin": "東京", "dest": "高尾",
  "x_m": 7535.8, "elapsed_s": 600.0, "sessions": 1 }
```

**打鍵に由来する値は、依然として 1 バイトも書かれていない。** 文字でも、
キーコードでも、打鍵数でも、いつ打ったかでもない。書いてあるのは
**電車がどこにいて、何秒走ったか**という、電車についての 2 つの数と、
その路線の名前だけ。読んでも、あなたについては何も分からない。

それを残しているのは、山手線が一周で、乗り切れない路線があるからです。
1 回で終わらない旅には、電車を一晩置く場所が要る。

`--fresh` を付ければ無視して乗り直せるし、終点に着けばファイルは消える。

VOICEVOX を使ったときだけ、`~/.demon/voice/` に放送の WAV がたまる。中身は
「次は、渋谷。」のような**決まった文を読み上げた音声**だけで、これも打鍵とは
無関係。消しても次に喋るときに作り直されるだけ。

`--demo` を付ければフックを一切張らず、ファイルも書かずに音だけ確認できる。

## 仕組み

**高い処理は起動時に 1 回だけ**やる、という一点で成り立っている。

1. `prepare()` で、周波数領域からノイズを合成する（`dsp.noise_loop`）。
   任意の振幅スペクトルにランダム位相を掛けて逆 FFT するので、
   出来上がりは**構造的にループする** —— 継ぎ目のクロスフェードもクリックもない。
   ジョイント音・ブレーキ・フランジ軋り・風鈴のような単発音も、ここで一度だけ作る。
2. リアルタイムのコールバックは、その出来合いのバッファを
   可変レートで読んで混ぜるだけ。IIR フィルタも FFT も走らない。

だから 1 ブロック（46 ms）あたりの計算は numpy の数十回の演算で終わり、
CPU 5%、確保するメモリも数 MB で収まる。

ミキシング中のバッファはチャンネル優先の `(2, n)` で持っている。
各デーモンが連続メモリに足し込めるようにするためで、サウンドカードに渡す
直前に一度だけ転置する。走行音や風切り音はモノラルをパンするのではなく、
同じループを離れた 2 か所から読んで左右を無相関にしてある
（モノラルをパンしただけだと音像が真ん中で潰れて、長時間だと疲れる）。

```
demon/
  dsp.py        ノイズ合成・ループ再生・単発音スケジューラ（numpy のみ）
  keywatch.py   打鍵 → 特徴量。文字は入り口で捨てる
  engine.py     ブロックループ・マスター・WAV 書き出し
  lines.py      3 路線の駅・距離・トンネル・曲線・分岐器
  route.py      運転。ノッチと制動と位置。音を一切知らない
  announce.py   モーラ → フォルマント。車内放送の合成と文面
  voice.py      VOICEVOX の肉声を天井スピーカーに通す（無ければフォルマントへ）
  journey.py    ディスクに触る唯一の場所（位置と時間だけ）
  picker.py     乗車。番号を打つだけの路線選択
  demons/
    base.py     デーモンの型
    train.py    電車デーモン
    cicada.py   蝉デーモン
```

`route.py` が音を一切知らないのは意図的で、おかげで物理は
オーディオデバイスなしで検証できる。実際、山手線一周が 61 分・
中央線特快 東京〜高尾が 54 分に収まることは、ヘッドレスで測って合わせてある
（どちらも実際のダイヤとほぼ同じ）。

> 駅間距離は営業キロで、経路の合計は公表値と一致する（山手線 34.5 km、
> 中央線 東京〜高尾 53.1 km、副都心線 20.2 km）。曲線と分岐器の位置は
> 実測ではなく、**その種類の線区がそれを持っている場所**に置いてある
> —— 地下鉄は曲がり続けるし、車庫のある駅は進入側に渡り線がある。
> 「お出口は右側です」の左右も実データではない。

## デーモンを足す

`Demon` を継承して `prepare()` と `render()` を書き、`demons/__init__.py` の
`REGISTRY` に登録するだけ。`render(out, rhythm, events, dt)` は
`(2, n)` の `out` に**足し込む**（上書きしない）。

雨（打鍵の強さ＝雨脚）、焚き火（`flow` が薪）、喫茶店（客の入りが `flow`）あたりは
同じ枠にそのまま乗る。
